# Сдвиг — регистрация на встречу

**Срок сдачи: 23.11.2026, 10:00**

## Запуск

```bash
npm install
npm run dev
```

Откройте **http://localhost:5173/**

## Инструменты

Для первой проверки достаточно браузера и [axe DevTools](https://www.deque.com/axe/devtools/extension/chrome/). Для ручной проверки используйте клавиатуру и один скринридер:

- Windows: [NVDA](https://www.nvaccess.org/download/), обычно вместе с Firefox или Chrome.
- macOS: VoiceOver (встроен в систему), обычно вместе с Safari.

## Ситуация

Встреча «Сдвиг» принимает заявки. Организаторы уже посмотрели страницу в Chrome с мышью: поля заполняются, ошибки показываются, подтверждение появляется. Перед запуском хотят понять, можно ли пройти тот же сценарий с клавиатуры и скринридером.

Ваша задача — провести короткий аудит, исправить наиболее важные проблемы и показать, что изменилось.

## Что должно работать

- Программа встречи открывается из верхнего меню и из блока с расписанием.
- В форме можно переключать формат: очно или онлайн.
- При пустых или ошибочных данных появляются сообщения.
- При заполненной форме и согласии показывается экран подтверждения.
- Можно вернуться к заявке и изменить данные.
- Письма НЕ отправляются.

0. Запишите окружение (ОС, браузер, скринридер и их версии).

1. Запустите проект и один раз зарегистрируйтесь мышью. Попробуйте отправить пустую форму, изменить формат участия, открыть программу и получить подтверждение. Убедитесь, что понимаете обычное поведение.

2. Проверьте отдельно c axe:

- исходную страницу;
- форму после отправки пустых полей;
- открытую программу встречи.

В заметках нужны не только числа, но и названия правил, какие элементы затронуты, что именно инструмент смог проверить.

3. Проверьте клавиатуру без мыши: Tab, Shift+Tab, Enter, пробел и Escape. Попробуйте последовательно:

- открыть программу, просмотреть её, закрыть и продолжить с того же места;
- выбрать **онлайн**, заполнить имя и email, отметить согласие;
- отправить пустую форму и разобраться, что требуется исправить.

4. Скринридер

Пройдите ключевой сценарий с NVDA или VoiceOver. Найдите форму, пройдите поля, вызовите валидацию и попробуйте завершить заявку.

5. Исправления

Выберите две проблемы. Лучше взять то, что мешает зарегистрироваться, закрывает результат и т.д. И исправьте их без изменения сценария, только средствами доступности. Их тоже внесите в отчет.

6. Проверка, что все работает (по тому же сценарию, как тестировали)
